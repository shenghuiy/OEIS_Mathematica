# A400000: the city-building sequence

`src/wolfram/A400000.wl` is a Wolfram Language package (context `OEIS`) for [A400000](https://oeis.org/A400000), "The city-building sequence: a(n) = the height h of the shortest building which can see exactly h earlier buildings" (Eric Fox, September 2026). It lists the first n terms with a compiled backward scan that skips blocks of buildings that cannot be seen, so each term takes a few dozen steps instead of a walk over the whole history.

## The sequence

Buildings stand at positions $1, 2, 3, \dots$, and building $n$ has height $a(n)$. A building of height $h$ at position $n$ *sees* the earlier building $i$ when every building in between has its top on or below the line joining the two tops:

$$a(k) \le a(i) + \frac{(h - a(i))(k - i)}{n - i} \quad \text{for all } i < k < n.$$

$a(n)$ is the least $h \ge 0$ such that a building of height $h$ at position $n$ sees exactly $h$ earlier buildings. The neighbouring building is always seen, and making a building taller never hides one, so the count is weakly increasing in $h$. Rémy Sigrist's comment on the entry uses this to show that such an $h$ always exists.

The first terms are

```
0, 1, 1, 2, 1, 2, 1, 3, 1, 2, 1, 3, 1, 2, 1, 10, 1, 2, 2, 3
```

Worked example, $a(16) = 10$: the counts of buildings seen from position 16 at heights $h = 0, 1, \dots, 10$ are 2, 3, 3, 4, 5, 7, 7, 8, 10, 10, 10. The count is above $h$ until $h = 10$, the first height where they are equal.

## Loading and calling

From the repository root:

```wolfram
Get["src/wolfram/A400000.wl"];
A400000[20]        (* {0, 1, 1, 2, 1, 2, 1, 3, 1, 2, 1, 3, 1, 2, 1, 10, 1, 2, 2, 3} *)
```

`A400000[n]` takes a positive integer `n` and returns the list $a(1), \dots, a(n)$; any other argument stays unevaluated. `?A400000` prints its usage message. It calls `a400000Pruned[n]`, the compiled function in `` OEIS`Private` ``; only `A400000` is public.

## How it works

### The scan on the OEIS page

The Python (Pontus von Brömssen) and Mathematica (Paolo Xausa) programs on the OEIS page try $h = 0, 1, 2, \dots$ in turn. For each $h$ they scan back from building $n - 1$ and keep the steepest line of sight found so far, rise $dy_0$ over run $dx_0$. Building $k$, at distance $dx = n - k$ and with $dy = a(k) - h$, is seen exactly when its slope is at least that steepest one, in integers

$$dx_0 \cdot dy \ge dx \cdot dy_0.$$

A scan stops as soon as more than $h$ buildings are seen, so the heights that fail end early. The height that succeeds cannot stop early: to be sure no further building is seen, it has to reach building 1. Each term costs $O(n)$ and the first $n$ terms $O(n^2)$.

### Skipping blocks

At distance $dx$ the line of sight needs a building of height at least $h + (dy_0/dx_0)\thinspace dx$. That bound is linear in $dx$, so a whole block of buildings $l, \dots, r$ is ruled out by its tallest building $B$ alone: if $B$ is below the bound at the block's lowest point, nothing in the block is seen. The lowest point is the near end $r$ when $dy_0 \ge 0$ and the far end $l$ when $dy_0 \lt 0$, which gives the integer test

$$(B - h)\thinspace dx_0 < dy_0 \cdot (n - r) \quad \text{or} \quad (B - h)\thinspace dx_0 < dy_0 \cdot (n - l).$$

The test only ever skips blocks with nothing visible in them; when it fails, the block may still hide nothing, and the scan looks closer.

`a400000Pruned` keeps the maximum height of every aligned block of $2^j$ buildings, for $j = 1, 2, \dots$, in one `FixedArray` (about $n$ entries in all). Placing building $m$ fills each block that it completes, $O(\log n)$ updates. The scan, at building $k$:

1. takes the largest aligned block that ends at $k$ (its size is the largest power of 2 dividing $k$, counted from 0);
2. skips it if the test passes, otherwise tries the next smaller size;
3. at size 1 the test is exact, and the building is seen or not as on the OEIS page.

Far back, the history is mostly old, low buildings well under the line of sight, so it falls into a few large blocks. In the Python prototype the scan looked at about 27 single buildings per term for $n = 10^4$ and about 30 for $n = 3 \times 10^5$, against about $n$ for the scan on the page. That count is measured, not proved: a skyline that kept the bound close to many block maxima would make the scan descend more often.

The arithmetic is in machine integers. The products are at most a height times a distance, far inside the 64-bit range for any `n` that fits in memory.

## Performance

Measured on the user's Windows machine with `wolframscript -file`. The page's program is its `Compile` code unchanged; `CompilationTarget -> "C"` found no C compiler, so it ran in the Wolfram virtual machine, as it does by default.

| n | OEIS page (`Compile`) | `A400000` |
|---|---|---|
| $10^4$ | 2.74 s | 0.012 s |
| $2 \times 10^4$ | 10.95 s | 0.036 s |
| $4 \times 10^4$ | 42.99 s | 0.075 s |
| $10^5$ | 354.9 s | 0.21 s |
| $10^6$ | | 1.8 s |
| $10^7$ | | 18.3 s |

Both returned the same lists at every n compared. Doubling n multiplies the page's time by about 4, while this package's time grows about in proportion to n (1.8 s for $10^6$ terms, 18.3 s for $10^7$). The first `Get` compiles `a400000Pruned` with `FunctionCompile`, about 50 s, once per kernel session.

## Checks run

`test/wolfram/A400000.wlt` has 13 cases, all passing in a fresh kernel:

- the first 120 terms, and all 10000 terms of Eric Fox's b-file (compared by SHA-256 of the list, so the test needs no network);
- the first 200 terms against a direct reading of the definition, with exact rational line tests and no slopes or skipping;
- for each $n \le 1000$, that $a(n)$ sees exactly $a(n)$ buildings and no smaller height sees exactly its own height;
- that a run of 1234 terms is the start of a run of 5000;
- the $10^6$ summary and the records up to $n = 2400000$ above;
- that only `A400000` is public, and that arguments other than positive integers stay unevaluated.

In a fresh kernel, `` Names["OEIS`*"] `` after `Get["src/wolfram/A400000.wl"]` is `{"A400000"}`.
