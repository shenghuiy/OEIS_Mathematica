# A401118: subsets of {1..n} with no LCM triangle

`src/wolfram/A401118.wl` is a Wolfram Language package (context `OEIS`) for [A401118](https://oeis.org/A401118). Call three distinct numbers $i, j, k$ an *LCM triangle* when $\operatorname{lcm}(i, j) = \operatorname{lcm}(j, k) = \operatorname{lcm}(k, i)$. Then $a(n)$ is the size of the largest subset of $\{1, \dots, n\}$ that contains no LCM triangle. Erdős problem [#536](https://www.erdosproblems.com/536) asks how $a(n)$ grows.

## The sequence

The terms for $n = 1, 2, 3, \dots$ begin

```
1, 2, 3, 4, 5, 5, 6, 7, 8, 9, 10, 10, 11, 12, 12, 13, 14, 15, 16, 16, ...
```

For example, $a(12) = 10$. The LCM triangles in $\{1..12\}$ are $\{2,3,6\}$, $\{2,5,10\}$, $\{3,4,12\}$ and $\{4,6,12\}$. Removing 2 and 4 breaks all four. One removal is not enough, because $\{2,5,10\}$ and $\{3,4,12\}$ share no element.

## Loading and calling

From the repository root:

```wolfram
Get["src/wolfram/A401118.wl"];
OEIS`LCMTriangles[12]            (* {{2,3,6}, {2,5,10}, {3,4,12}, {4,6,12}} *)
OEIS`A401118[12]                 (* 10 *)
OEIS`A401118List[20]             (* the 20 terms above *)
OEIS`LCMTriangleFreeSubset[12]   (* a subset of size 10 with no LCM triangle *)
Length[OEIS`LCMTriangles[656]]   (* 6225 *)
OEIS`A401118List[200, Method -> "LinearOptimization"]   (* without SCIP *)
```

## Public functions

| Call | Returns |
|---|---|
| `A401118[n]` | $a(n)$. |
| `A401118List[nmax]` | $\{a(1), \dots, a(n_{\max})\}$. |
| `LCMTriangles[n]` | Every LCM triangle $\{i, j, k\}$ with $i < j < k \le n$, sorted by $k$ and then $i$. |
| `LCMTriangleFreeSubset[n]` | A subset of $\{1..n\}$ of size $a(n)$ with no LCM triangle. |

The argument is a positive integer. Otherwise the function gives a `::posint` message and returns `$Failed`. Every function computes the terms from $1$ up, so `A401118[n]` costs as much as `A401118List[n]`.

`A401118`, `A401118List` and `LCMTriangleFreeSubset` take a `Method` option that picks the integer solver:

| `Method` | Solver |
|---|---|
| `Automatic` (default) | SCIP if [its library](#building-the-scip-library) is found, otherwise `LinearOptimization`. |
| `"SCIP"` | SCIP, through `ForeignFunctionLoad`. Without the library, gives a `::noscip` message and returns `$Failed`. |
| `"LinearOptimization"` | Mathematica's built-in integer solver. |

Any other value gives a `::method` message and returns `$Failed`. All methods give the same terms, but the witness from `LCMTriangleFreeSubset` may differ, since a largest subset is not unique. If SCIP returns an error code, the package gives `A401118::scipfail` and solves that problem with `LinearOptimization` instead.

## How it works

### LCM triangles from prime exponents

$i, j, k$ form an LCM triangle exactly when, for every prime $p$, the largest exponent of $p$ among the three occurs at least twice. Fix the largest element $m$ and a smaller element $i$, and let $G = \gcd(i, m)$ and $L = \operatorname{lcm}(i, m)$. A prime divides $r = L/G$ exactly when its exponents in $i$ and $m$ differ, and then the third element $k$ must carry the larger exponent. Where the exponents are equal, $k$ may carry any exponent up to that value. So $k = A d$, where $g$ is the part of $G$ coprime to $r$, $A = L/g$, and $d$ divides $g$. When $A \ge m$ there is no such $k$.

`lcmTrianglesC` is a `FunctionCompile`d loop over $m$ and $i < m$ that applies this rule using only `GCD`, `Quotient` and `Mod`, so it never factors anything. It finds the 6,225 triangles up to 656 in 0.01 s, and the 37,049 up to 2000 in 0.12 s. Testing all $\binom{n}{3}$ triples instead takes 3 s just to reach 656.

### One term at a time

The OEIS entry notes that $a(m-1) \le a(m) \le a(m-1) + 1$. So each new term asks one question: is there a triangle-free subset of $\{1..m\}$ with $a(m-1) + 1$ elements? Such a subset must contain $m$, and the only new triangles are those whose largest element is $m$. The package keeps a witness $S$ for $a(m-1)$ and proceeds as follows:

1. If no new triangle has both of its smaller elements in $S$, then $S \cup \{m\}$ is triangle-free and $a(m) = a(m-1) + 1$, with no solve. This covers every $m$ that lies in no triangle, such as 1 and the primes, and most other terms too.
2. Otherwise the solver (SCIP or `LinearOptimization`) maximizes $\sum x_v$ over 0-1 variables $x_v$. Only numbers that lie in some triangle get a variable, since the others can always be added. If the maximum, plus the number of numbers in no triangle, reaches $a(m-1) + 1$, the solution becomes the new witness. Otherwise $a(m) = a(m-1)$ and $S$ is kept.

Up to $n = 200$, 72 of the 200 terms needed a solve. The solves that found no larger set, where the term stays at $a(m-1)$, took 43.3 s of the 43.7 s spent solving.

### Clique constraints

All three pairs of a triangle have the same LCM $L$. Fix $L$ and join two numbers when their LCM is $L$. In a clique of that graph, every three elements form a triangle, so at most two of them can be kept. The package therefore uses one constraint $\sum x \le 2$ per maximal clique (`FindClique`) instead of one per triangle. An example is $\{6, 10, 15, 30\}$, whose pairwise LCMs are all 30. At each step, only the cliques of LCMs that gained a triangle are recomputed. For $m = 198$ (173 variables), the 857 triangles become 721 cliques, 51 of them of size 4.

Timings for that problem, where 145 elements turn out to be impossible:

| Formulation | Solver | Time |
|---|---|---|
| Feasibility ($\sum x \ge$ target), one constraint per triangle | `LinearOptimization` | 7.6 s |
| Feasibility, one constraint per clique | `LinearOptimization` | 4.6 s |
| Maximize $\sum x$, one constraint per clique (used) | `LinearOptimization` | 3.7 s |
| Maximize $\sum x$, one constraint per clique (used) | SCIP | 0.75 s |

Two ideas did not help and are not used:

- **Prefix cuts:** $\sum_{v \le m'} x_v \le a(m')$ for the known earlier terms. These are valid, but they made each solve 2 to 3 times slower.
- **Merging large primes:** primes $p > \sqrt m$ with the same $\lfloor m/p \rfloor$ have isomorphic sets of multiples, so one representative with a weight could stand in for all of them. The optimum is the same, but the time stayed at 3.7 s.

### SCIP through `ForeignFunctionLoad`

[`src/c/a401118_scip/a401118_scip.c`](../src/c/a401118_scip/a401118_scip.c) is a small C function on top of [SCIP](https://github.com/scipopt/scip)'s C API. It takes the model as flat arrays: the number of variables, their weights (all 1 here), and the cliques in compressed form, as start offsets plus 0-based variable indices. It builds one binary variable per number and one linear constraint $\sum x \le 2$ per clique, solves, and writes the 0-1 solution into an output array. It returns the optimum, or a negative error code.

The package loads it once per session with `ForeignFunctionLoad` and passes the arrays with `RawMemoryExport`. It looks for the library in `src/c/a401118_scip/lib`, or in the directory named by the environment variable `A401118_SCIP_LIB`. A failed lookup is remembered too, so restart the kernel after building. On Windows, a DLL's dependencies are found on `PATH`, not next to it, so the package first loads `libsoplexshared.dll` and `libscip.dll` from that directory with `LibraryLoad`.

### Building the SCIP library

These steps were run on Windows with Visual Studio 2022 (MSVC 14.44, using its bundled CMake and Ninja) and SCIP Opt Suite 10.1.0. Run them from an "x64 Native Tools" prompt. Keep the SCIP build directory short (`C:\Users\sheng\AppData\Local\Temp\scip` here), because MSVC fails with `C1083` on long paths.

1. Download `scipoptsuite-10.1.0.tgz` from the [SCIP releases](https://github.com/scipopt/scip/releases) and unpack it, here to `<scip>\src`.
2. Build SCIP with SoPlex and nothing optional, as shared libraries:

   ```bat
   cmake -S <scip>\src -B <scip>\b -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=<scip>\inst ^
     -DAUTOBUILD=OFF -DGCG=OFF -DUG=OFF -DPAPILO=OFF -DZIMPL=OFF -DGMP=OFF -DMPFR=OFF -DREADLINE=OFF -DZLIB=OFF ^
     -DIPOPT=OFF -DAMPL=OFF -DBOOST=OFF -DCLIQUER=OFF -DJANSSON=OFF -DLUSOL=OFF -DQUADMATH=OFF -DSHARED=ON -DLPS=spx
   cmake --build <scip>\b --parallel
   cmake --install <scip>\b
   ```

3. Build the wrapper from the repository root. This writes `a401118_scip.dll` to `src/c/a401118_scip/lib`, and on Windows copies SCIP's DLLs there too (`build/` and `lib/` are in `.gitignore`):

   ```bat
   cmake -S src/c/a401118_scip -B src/c/a401118_scip/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DSCIP_DIR=<scip>/inst/lib/cmake/scip
   cmake --build src/c/a401118_scip/build
   ```

On macOS and Linux the same CMake steps apply. The wrapper is then `a401118_scip.dylib` or `.so`, and it finds SCIP through its build RPATH. That route has not been tried.

## Performance

Measured with Mathematica 15.0.1 on Windows, with SCIP 10.1.0 built as above. Gurobi, CPLEX, Xpress and MOSEK are not installed there. Each run starts from $n = 1$ and was checked against the b-file.

| | SCIP | `LinearOptimization` |
|---|---|---|
| Loading the package (compiling `lcmTrianglesC`) | about 38 s | about 38 s |
| `A401118List[150]` | 5.0 s | 7.0 s |
| `A401118List[200]` | 16.3 s | 56.0 s |
| `A401118List[300]` | 82.6 s | 266.7 s |

The time grows quickly with $n$, since the integer programs that prove no larger set exists get harder. The entry's 656 terms were computed with SCIP and HiGHS; this package has been checked against them only up to $n = 300$.

## Checks run

Run `test/wolfram/A401118.wlt` (22 cases, about 1 minute, most of it the compile at load). The cases that don't name a method use `Automatic`, so they test SCIP when its library is built. It checks:

- The examples above and the OEIS DATA section.
- The b-file up to $n = 150$.
- `LCMTriangles[80]` against testing every triple.
- $a(n)$ against brute force over all subsets of $\{1..14\}$.
- That `LCMTriangleFreeSubset[120]` is triangle-free with 88 elements.
- The entry's formulas up to 150: $a(n+1) - a(n) \in \{0, 1\}$, $a(p) = a(p-1) + 1$ for primes $p$, and $a(n) \le n - \lfloor n/6 \rfloor$.
- That `Method -> "LinearOptimization"` gives the same 150 terms as `Automatic`.
- That `Automatic` picks SCIP exactly when the library is found.
- That `Method -> "SCIP"`, when built, gives the right terms and a valid witness for $n = 120$.
- That without the library, `Automatic` falls back and `"SCIP"` gives `::noscip`.
- That only the four public names are in `` OEIS` ``.
- The messages for invalid arguments, including an unknown method.

Separately, `A401118List[300]` with both methods, and the SCIP witness for $n = 300$, were checked against the b-file.
