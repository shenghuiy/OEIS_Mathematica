# A401118 by integer linear programming

`src/wolfram/A401118ILP.wl` is a Wolfram Language package (context `OEIS`) that computes [A401118](https://oeis.org/A401118), the size of the largest subset of $\lbrace 1, \dots, n\rbrace$ with no *LCM triangle*: three numbers whose pairwise LCMs are all equal. It solves the problem as an integer linear program, the way the OEIS entry's b-file (n ≤ 656) was computed. The sequence itself, its examples and an exhaustive search for small $n$ are on the [A401118](A401118.md) page.

## Loading and calling

From the repository root:

```wolfram
Get["src/wolfram/A401118ILP.wl"];
OEIS`A401118ILP[100]      (* 76, in about 0.1 s *)
```

`A401118ILP[n]` takes a positive integer `n` and returns $a(n)$. The private helper `` OEIS`Private`a401118ILPSet[n] `` returns an optimal subset itself, sorted.

## How it works

1. **LCM cliques.** In an LCM triangle $\lbrace x, y, z\rbrace$, all three pairs have the same LCM $L$. So the code groups the pairs of $\lbrace 1..n\rbrace$ by LCM. For each $L$ it builds the graph whose edges are the pairs with that LCM; the LCM triangles are exactly the triangles of these graphs. `a401118Cliques` lists each graph's maximal cliques with 3 or more vertices (`FindClique`). For $n = 12$ these are $\lbrace 2, 3, 6\rbrace$, $\lbrace 2, 5, 10\rbrace$, $\lbrace 3, 4, 12\rbrace$ and $\lbrace 4, 6, 12\rbrace$.
2. **The program.** Each number in some clique gets a 0/1 variable $x_i$. The program maximizes $\sum x_i$ subject to $\sum_{i \in C} x_i \le 2$ for every clique $C$. Any three numbers in a clique form an LCM triangle, and every triangle lies in some clique, so these constraints say exactly "no LCM triangle". The numbers in no clique are always taken.
3. **Solving.** `LinearOptimization` with integer variables solves it, using CBC (what `Method -> Automatic` picks).

One constraint per maximal clique, rather than one per triangle, makes the LP relaxation tighter. At $n = 200$ that is 732 constraints instead of 868, and the solve takes 4.3 s instead of 7.5 s.

## Performance

Measured on Windows 11 with Mathematica 15.0.1, in a local kernel:

| n | $a(n)$ | time |
|---|---|---|
| 1 to 73 (all DATA terms) | | 1.3 s |
| 100 | 76 | 0.08 s |
| 200 | 146 | 4.1 s |
| 300 | 218 | 12.8 s |
| 400 | 290 | 45 s |

The exhaustive search in `A401118.wl` takes 27 s at $n = 30$; at $n = 100$ it would not finish.

## Checks run

`test/wolfram/A401118ILP.wlt` (10 cases, about 7 s) checks:

- The whole OEIS DATA section ($n \le 73$), and the b-file values at $n$ = 100, 150, 200.
- That every clique has all pairwise LCMs equal, and that the cliques cover every LCM triangle in $\lbrace 1..40\rbrace$, found by brute force.
- That the optimal subset for $n = 60$ has the right size and contains no LCM triangle.
- That there are no cliques for $n \le 5$; the cliques for $n = 6$; and $a(100) = 76$.
- That only `A401118ILP` is in the public `` OEIS` `` context.

The values at $n$ = 250, 300 and 400 (185, 218, 290) also match the b-file. They are not in the tests because they take too long.
