# A399539: numbers k with ψ(k) − φ(k) = d(k)⁴

`src/wolfram/A399539.wl` is a Wolfram Language package (context `OEIS`) that lists the terms of [A399539](https://oeis.org/A399539), titled "Numbers k such that psi(k) = phi(k) + tau(k)^4" (S. I. Dimitrov, September 2026). It finds every term up to a bound with a compiled segmented sieve.

## The sequence

A399539 lists the k with

ψ(k) − φ(k) = d(k)⁴

where ψ is the Dedekind psi function, φ is Euler's totient and d (the OEIS entry's τ) is the number of divisors. All three are multiplicative, so they are fixed by their values on prime powers:

| | on pᵃ |
|---|---|
| φ(pᵃ) | pᵃ⁻¹(p − 1) |
| ψ(pᵃ) | pᵃ⁻¹(p + 1) |
| d(pᵃ) | a + 1 |

Worked example, the first term: 2071 = 19 × 109, so

- ψ = 20 × 110 = 2200
- φ = 18 × 108 = 1944
- ψ − φ = 256 = 4⁴, and d = 2 × 2 = 4.

The number 1 is not a term: ψ(1) − φ(1) = 0, while d(1)⁴ = 1.

## Loading and calling

From the repository root:

```wolfram
Get["src/wolfram/A399539.wl"];
OEIS`A399539[10^4]      (* {2071, 3007, 4087} *)
```

`A399539[n]` takes a positive integer `n` and returns, in increasing order, every k ≤ n that satisfies the condition. It is a thin wrapper: `A399539[n_Integer?Positive] := isokSeg[n, 2^16]`.

`isokSeg[nmax, bsize]` is the compiled function that does the work. The file's comments call it private, but the symbol is created before `Begin["`Private`"]`, so it is really `OEIS`isokSeg` and can be called directly. The package also leaves a stray symbol `OEIS`n`.

## How it works

`isokSeg` is built with `FunctionCompile`, so the loops run as native machine code instead of interpreted Wolfram Language. Compiled code accepts only a restricted set of functions, so it does its own factoring with a sieve instead of calling `FactorInteger` n times.

1. **Primes up to √nmax.** A plain sieve of Eratosthenes, run once, stores the primes up to ⌊√nmax⌋ + 1 in a `FixedArray`.
2. **Blocks.** The range 1..nmax is cut into blocks of `bsize` = 2¹⁶ consecutive numbers, so the working arrays stay small. Each block has four arrays:
   - `rem`: the part of each number not yet factored; it starts as the number itself.
   - `psi`, `phi`, `d`: running products, each starting at 1.
3. **Sieving a block.** For each prime p with p² ≤ hi (hi is the top of the block), the loop starts at `Max[p*p, p*Quotient[lo+p-1, p]]`: the first multiple of p in the block, but never below p². For each multiple m it divides out every power pᵉ of p from `rem` and multiplies the contribution into the arrays:
   - `psi` by (p + 1) pᵉ⁻¹
   - `phi` by (p − 1) pᵉ⁻¹
   - `d` by (e + 1)

   The first `Quotient` needs no divisibility test, because p | m by construction. Only the further divisions test the remainder, which saves a `Mod` on most of the roughly 3n hits.
4. **Leftover prime.** After the sieve, any `rem > 1` is a single prime. A number ≤ hi cannot have two distinct prime factors that both exceed √hi, and every prime up to √hi has been divided out. (Example: 6 is skipped by p = 3 since 9 > 6, and the 3 stays in `rem`.) The cleanup step multiplies in (r + 1), (r − 1) and 2 for that prime. This avoids sieving all the way up to n.
5. **Test.** For each number the code checks `psi − phi == d^4`. Matches go into a `DynamicArray`, returned as `res["Elements"]`.

## Performance

Measured on this machine (MacBook Pro, Apple M1 Max, 32 GB, Mathematica 15.0.1, run with `wolframscript -file`):

| Measurement | Observed | Source |
|---|---|---|
| `A399539[10^8]` | 5.17 s and 5.16 s (two runs) | this machine |
| `A399539[10^8]` | 4.74 s, MacBook Pro M1 Max, 32 GB | benchmark in `src/wolfram/A399539.wl` |
| `A399539[10^4]` | 0.0004 s (after loading) | this machine |
| First `Get["src/wolfram/A399539.wl"]` | 28.6 s | this machine |
| `Select` over built-ins, k ≤ 10⁶ | 7.6 s | this machine |

The one-time cost is `FunctionCompile` on the first `Get`: it is paid once per kernel session, and the 28.6 s was measured with `wolframscript`, which shows a compile-progress display. The file's benchmark was recorded on the same model of machine; this machine's two runs are about 9% slower, and the cause was not investigated.

The code uses machine integers (`MachineInteger`), so `n` and the intermediate products must stay within the signed 64-bit range (up to 9223372036854775807). That limit was not tested; the practical limit is run time, which grows roughly linearly with n.

## Checks run

- `A399539[10^4]` gave `{2071, 3007, 4087}`.
- `A399539[10^5]` and `A399539[10^6]` match `Select[Range[n], k > 1 && DivisorSigma[0, k]^4 == k Times @@ (1 + 1/First /@ FactorInteger[k]) − EulerPhi[k]]`. The `k > 1` guard is needed because `FactorInteger[1]` returns `{{1, 1}}`, which makes the product formula give ψ(1) = 2 and wrongly accept 1.
- The result does not depend on the block size: `OEIS`isokSeg[10^6, 2^10]` equals `OEIS`isokSeg[10^6, 2^16]`, and block sizes 7 and 1000 agree with 2¹⁶ at 10⁵.
