# A399539: numbers $k$ with $\psi(k) - \varphi(k) = d(k)^4$

`src/wolfram/A399539.wl` is a Wolfram Language package (context `OEIS`) that lists the terms of [A399539](https://oeis.org/A399539), titled "Numbers k such that psi(k) = phi(k) + tau(k)^4" (S. I. Dimitrov, September 2026). It finds every term up to a bound with a compiled segmented sieve.

## The sequence

A399539 lists the $k$ with

$$\psi(k) - \varphi(k) = d(k)^4$$

where $\psi$ is the Dedekind psi function, $\varphi$ is Euler's totient and $d$ (the OEIS entry's $\tau$) is the number of divisors. All three are multiplicative, so they are fixed by their values on prime powers:

| | on $p^a$ |
|---|---|
| $\varphi(p^a)$ | $p^{a-1}(p - 1)$ |
| $\psi(p^a)$ | $p^{a-1}(p + 1)$ |
| $d(p^a)$ | $a + 1$ |

Worked example, the first term: $2071 = 19 \times 109$, so

- $\psi = 20 \times 110 = 2200$
- $\varphi = 18 \times 108 = 1944$
- $\psi - \varphi = 256 = 4^4$, and $d = 2 \times 2 = 4$.

The number 1 is not a term: $\psi(1) - \varphi(1) = 0$, while $d(1)^4 = 1$.

## Loading and calling

From the repository root:

```wolfram
Get["src/wolfram/A399539.wl"];
OEIS`A399539[10^4]      (* {2071, 3007, 4087} *)
```

`A399539[n]` takes a positive integer `n` and returns, in increasing order, every $k \le n$ that satisfies the condition; `?A399539` prints its usage message. It is a thin wrapper: `A399539[n_Integer?Positive] := isokSeg[n, 2^16]`.

`isokSeg[nmax, bsize]` is the compiled function that does the work. It lives in `` OEIS`Private` ``; only `A399539` is public. To try another block size, call it by its full name, `` OEIS`Private`isokSeg ``.

## How it works

`isokSeg` is built with `FunctionCompile`, so the loops run as native machine code instead of interpreted Wolfram Language. Compiled code accepts only a restricted set of functions, so it does its own factoring with a sieve instead of calling `FactorInteger` n times.

1. **Primes up to $\sqrt{n_{\max}}$.** A plain sieve of Eratosthenes, run once, stores the primes up to $\lfloor\sqrt{n_{\max}}\rfloor + 1$ in a `FixedArray`.
2. **Blocks.** The range 1..nmax is cut into blocks of `bsize` = $2^{16}$ consecutive numbers, so the working arrays stay small. Each block has four arrays:
   - `rem`: the part of each number not yet factored; it starts as the number itself.
   - `psi`, `phi`, `d`: running products, each starting at 1.
3. **Sieving a block.** For each prime $p$ with $p^2 \le hi$ ($hi$ is the top of the block), the loop starts at `Max[p*p, p*Quotient[lo+p-1, p]]`: the first multiple of $p$ in the block, but never below $p^2$. For each multiple $m$ it divides out every power $p^e$ of $p$ from `rem` and multiplies the contribution into the arrays:
   - `psi` by $(p + 1)\, p^{e-1}$
   - `phi` by $(p - 1)\, p^{e-1}$
   - `d` by $(e + 1)$

   The first `Quotient` needs no divisibility test, because $p \mid m$ by construction. Only the further divisions test the remainder, which saves a `Mod` on most of the roughly 3n hits.
4. **Leftover prime.** After the sieve, any `rem > 1` is a single prime. A number $\le hi$ cannot have two distinct prime factors that both exceed $\sqrt{hi}$, and every prime up to $\sqrt{hi}$ has been divided out. (Example: 6 is skipped by $p = 3$ since $9 > 6$, and the 3 stays in `rem`.) The cleanup step multiplies in $(r + 1)$, $(r - 1)$ and 2 for that prime. This avoids sieving all the way up to n.
5. **Test.** For each number the code checks `psi − phi == d^4`. Matches go into a `DynamicArray`, returned as `res["Elements"]`.

## Performance

Measured on this machine (MacBook Pro, Apple M1 Max, 32 GB, Mathematica 15.0.1, run with `wolframscript -file`):

| Measurement | Observed | Source |
|---|---|---|
| `A399539[10^8]` | 5.17 s and 5.16 s (two runs) | this machine |
| `A399539[10^8]` | 4.74 s, MacBook Pro M1 Max, 32 GB | benchmark in `src/wolfram/A399539.wl` |
| `A399539[10^4]` | 0.0004 s (after loading) | this machine |
| First `Get["src/wolfram/A399539.wl"]` | 28.6 s | this machine |
| `Select` over built-ins, $k \le 10^6$ | 7.6 s | this machine |

The one-time cost is `FunctionCompile` on the first `Get`: it is paid once per kernel session, and the 28.6 s was measured with `wolframscript`, which shows a compile-progress display. The file's benchmark was recorded on the same model of machine; this machine's two runs are about 9% slower, and the cause was not investigated.

The code uses machine integers (`MachineInteger`), so `n` and the intermediate products must stay within the signed 64-bit range (up to 9223372036854775807). That limit was not tested; the practical limit is run time, which grows roughly linearly with $n$.

## Checks run

- `A399539[10^4]` gave `{2071, 3007, 4087}`.
- `A399539[10^5]` and `A399539[10^6]` match `Select[Range[n], k > 1 && DivisorSigma[0, k]^4 == k Times @@ (1 + 1/First /@ FactorInteger[k]) − EulerPhi[k]]`. The `k > 1` guard is needed because `FactorInteger[1]` returns `{{1, 1}}`, which makes the product formula give $\psi(1) = 2$ and wrongly accept 1.
- The result does not depend on the block size: `` OEIS`Private`isokSeg[10^6, 2^10] `` equals `` OEIS`Private`isokSeg[10^6, 2^16] ``, and block sizes 7 and 1000 agree with 2¹⁶ at 10⁵.
- In a fresh kernel, `` Names["OEIS`*"] `` after `Get["src/wolfram/A399539.wl"]` is `{"A399539"}`.
