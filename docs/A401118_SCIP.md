# A401118_SCIP: A401118 by integer linear programming with SCIP

`src/wolfram/A401118_SCIP.wl` is a Wolfram Language package (context `OEIS`) that computes [A401118](https://oeis.org/A401118). That is the size of the largest subset of $\lbrace 1, \dots, n\rbrace$ with no *LCM triangle*: three numbers whose pairwise LCMs are all equal. It solves the problem as one integer linear program per $n$, as the OEIS entry's b-file ($n \le 656$) was computed. The solver is [SCIP](https://github.com/scipopt/scip), called through `ForeignFunctionLoad` on the C wrapper in [`src/c/a401118_scip`](../src/c/a401118_scip). Without that library the same program goes to `LinearOptimization`.

The sequence itself, its examples and the exhaustive search for small $n$ are on the [A401118](A401118.md) page.

## Loading and calling

From the repository root:

```wolfram
Get["src/wolfram/A401118_SCIP.wl"];
A401118SCIP[100]                                  (* 76 *)
A401118SCIP[400]                                  (* 290, in 12 s with SCIP *)
A401118SCIP[300, Method -> "LinearOptimization"]  (* 218, without SCIP *)
A401118SCIP[12, "Subset"]                        (* {1, 3, 4, 5, 6, 7, 8, 9, 10, 11}, one of several optimal subsets *)
```

`A401118SCIP` is the only public function. Its second argument picks what it returns:

| Call | Result |
|---|---|
| `A401118SCIP[n]`, `A401118SCIP[n, "Size"]` | $a(n)$, the size of a largest subset with no LCM triangle. |
| `A401118SCIP[n, "Subset"]` | One such subset, sorted. Which optimal subset comes back depends on the solver. |

Its `Method` option picks the solver:

| `Method` | Solver |
|---|---|
| `Automatic` (default) | SCIP if [its library](#building-the-scip-library) is found, otherwise `LinearOptimization`. |
| `"SCIP"` | SCIP. Without the library, gives a `::noscip` message and returns `$Failed`. |
| `"LinearOptimization"` | Mathematica's built-in integer solver. |

Any other value gives a `::method` message and returns `$Failed`, and so does a second argument other than `"Size"` or `"Subset"` (`::prop`) or a first argument that is not a positive integer (`::posint`). If SCIP returns an error code, the package gives `A401118SCIP::scipfail` and solves the problem with `LinearOptimization` instead.

## How it works

### LCM cliques

In an LCM triangle $\lbrace x, y, z\rbrace$, all three pairs have the same LCM $L$. So the package groups the pairs of $\lbrace 1..n\rbrace$ by LCM. For each $L$ it builds the graph whose edges are the pairs with that LCM; the LCM triangles are exactly the triangles of these graphs. Any three numbers in a clique of one graph form an LCM triangle, so a valid subset takes at most two numbers from each clique. For example, 6, 10, 15 and 30 have pairwise LCM 30, so at most two of them can be kept. `a401118SCIPCliques` lists the maximal cliques with 3 or more vertices (`FindClique`); every LCM triangle lies in one of them.

### The integer linear program

There is one 0/1 variable for each number that lies in some clique. The program maximizes their sum, subject to $\sum x \le 2$ for every clique. The numbers in no clique are always taken. One constraint per maximal clique, rather than one per triangle, makes the LP relaxation tighter.

A solver is a function `solve[vars, cliques]` that returns the variables set to 1, and `a401118SCIPSet[n, solve]` returns an optimal subset. There are two solvers:
- `a401118LPSolve` calls `LinearOptimization`.
- `a401118SCIPSolve` calls the C wrapper.

### The C wrapper

[`a401118_scip.c`](../src/c/a401118_scip/a401118_scip.c) is a small C function on top of SCIP's C API. It takes the model as flat arrays: the number of variables, their weights (all 1 here), and the cliques in compressed form, as start offsets plus 0-based variable indices. It builds one binary variable per number and one linear constraint $\sum x \le 2$ per clique, solves, and writes the 0/1 solution into an output array. It returns the optimum, or a negative error code:

| Code | Meaning |
|---|---|
| -2 | A SCIP call failed. |
| -3 | `SCIPcreate` failed. |
| -4 | A clique has more than 64 elements. |
| -5 | Not solved to optimality. |

### Loading it

The package loads the wrapper once per session with `ForeignFunctionLoad` and passes the arrays with `RawMemoryExport`. It looks for `a401118_scip.dll` (`.dylib`, `.so`) in `lib/` at the repository root, or in the directory named by the environment variable `A401118_SCIP_LIB`. A failed lookup is remembered too, so restart the kernel after building. On Windows, a DLL's dependencies are found on `PATH`, not next to it, so the package first loads `libsoplexshared.dll` and `libscip.dll` from that directory with `LibraryLoad`.

## Building the SCIP library

SCIP and SoPlex, the LP solver SCIP uses, are git submodules at the repository root, pinned to their release tags:

| Path | Repository | Tag |
|---|---|---|
| `scip/` | [scipopt/scip](https://github.com/scipopt/scip) | v10.1.0 |
| `soplex/` | [scipopt/soplex](https://github.com/scipopt/soplex) | v8.1.0 |

Everything is built under `build/` and installed to `build/install`; the wrapper and the DLLs it needs end up in `lib/`. Both `build/` and `lib/` are in `.gitignore`.

These steps were run on Windows with Visual Studio 2022 (MSVC 14.44, using its bundled CMake and Ninja), from an "x64 Native Tools" prompt at the repository root. MSVC fails with `C1083` when paths get too long, so keep the checkout's path short.

1. Fetch the submodules (they are shallow):

   ```bat
   git submodule update --init --depth 1
   ```

2. Build and install SoPlex, then SCIP with SoPlex and nothing optional, as shared libraries:

   ```bat
   cmake -S soplex -B build/soplex -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=build/install -DGMP=OFF -DMPFR=OFF -DBOOST=OFF -DZLIB=OFF -DQUADMATH=OFF
   cmake --build build/soplex --parallel
   cmake --install build/soplex
   cmake -S scip -B build/scip -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=build/install -DSOPLEX_DIR=build/install/lib/cmake/soplex ^
     -DAUTOBUILD=OFF -DPAPILO=OFF -DZIMPL=OFF -DGMP=OFF -DREADLINE=OFF -DZLIB=OFF -DIPOPT=OFF -DAMPL=OFF -DSHARED=ON -DLPS=spx
   cmake --build build/scip --parallel
   cmake --install build/scip
   ```

3. Build the wrapper. It finds SCIP in `build/install` (or pass `-DSCIP_DIR=<install>/lib/cmake/scip`), writes `a401118_scip.dll` to `lib/`, and on Windows copies `libscip.dll` and `libsoplexshared.dll` there too:

   ```bat
   cmake -S src/c/a401118_scip -B build/a401118_scip -G Ninja -DCMAKE_BUILD_TYPE=Release
   cmake --build build/a401118_scip
   ```

On macOS and Linux the same CMake steps apply. The wrapper is then `a401118_scip.dylib` or `.so`, and it finds SCIP through its build RPATH. That route has not been tried.

## Performance

Measured with Mathematica 15.0.1 on Windows, with SCIP 10.1.0 (from the SCIP Opt Suite release, the same code as the submodules) built as above. Every value matches the b-file.

| $n$ | $a(n)$ | SCIP | `LinearOptimization` |
|---|---|---|---|
| 100 | 76 | 0.07 s | 0.16 s |
| 200 | 146 | 1.8 s | 3.7 s |
| 300 | 218 | 5.2 s | 13.5 s |
| 400 | 290 | 12.1 s | 40.1 s |
| 500 | 356 | 38.3 s | |
| 656 | 464 | 365 s | |

With SCIP, every b-file term can be checked this way: $n = 656$, the last one, takes 6 minutes. The package compiles nothing, so loading it takes no measurable time.

## Checks run

Run `test/wolfram/A401118_SCIP.wlt` (19 cases, about 5 s). Cases that can run `LinearOptimization` keep $n < 20$. The SCIP case runs only with the library built, and passes trivially without it. It checks:

- That `A401118SCIP` is the only public name, and that its option is `Method -> Automatic`.
- The examples above, and the first 19 DATA terms with each method.
- That the cliques have equal pairwise LCMs (up to 60) and cover every LCM triangle (up to 40, against brute force), and that there are none below 6.
- That `"Subset"` gives $a(n)$ elements of $\lbrace 1..n\rbrace$ with no LCM triangle, for $n = 12$ and, with each method, $n = 19$.
- That `Automatic` picks SCIP exactly when the library is found, and that without it `Automatic` falls back and `"SCIP"` gives `::noscip`.
- With SCIP: the whole DATA section, the b-file at 100, 150 and 200, and that `"Subset"` for 150 is triangle-free of size $a(150) = 111$.
- The messages for an unknown method, an unknown property and a bad first argument.
