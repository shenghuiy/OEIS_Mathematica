# A401118_SCIP: SCIP for the A401118 package

`src/wolfram/A401118_SCIP.wl` adds a `Method` option to the [A401118 package](A401118.md). The option picks the solver for the package's 0-1 programs. With [SCIP](https://github.com/scipopt/scip), called through `ForeignFunctionLoad`, `A401118List[300]` takes 82.6 s instead of 266.7 s with `LinearOptimization`. The C code is in [`src/c/a401118_scip`](../src/c/a401118_scip).

## Loading and calling

From the repository root:

```wolfram
Get["src/wolfram/A401118_SCIP.wl"];   (* loads A401118.wl too, if it is not loaded yet *)
OEIS`A401118[200]                                      (* 146, with SCIP if its library is built *)
OEIS`A401118List[200, Method -> "LinearOptimization"]  (* without SCIP *)
OEIS`LCMTriangleFreeSubset[120, Method -> "SCIP"]      (* fails with ::noscip if the library is missing *)
```

The package adds no public names. It puts the option on `A401118`, `A401118List` and `LCMTriangleFreeSubset` from `A401118.wl`, and replaces their `::usage` text to mention it. `LCMTriangles` uses no solver, so it gets no option.

## The `Method` option

| `Method` | Solver |
|---|---|
| `Automatic` (default) | SCIP if [its library](#building-the-scip-library) is found, otherwise `LinearOptimization`. |
| `"SCIP"` | SCIP. Without the library, gives a `::noscip` message and returns `$Failed`. |
| `"LinearOptimization"` | Mathematica's built-in integer solver, as in `A401118.wl` alone. |

Any other value gives a `::method` message and returns `$Failed`. Calls without options, such as `A401118[200]`, use `Automatic` once this package is loaded. All methods give the same terms. The subset from `LCMTriangleFreeSubset` may differ, though, since a largest subset is not unique. If SCIP returns an error code, the package gives `A401118::scipfail` and solves that problem with `LinearOptimization` instead.

## How it works

### The C wrapper

[`a401118_scip.c`](../src/c/a401118_scip/a401118_scip.c) is a small C function on top of SCIP's C API. It takes the model as flat arrays: the number of variables, their weights (all 1 here), and the cliques in compressed form, as start offsets plus 0-based variable indices. It builds one binary variable per number and one linear constraint $\sum x \le 2$ per clique, solves, and writes the 0-1 solution into an output array. It returns the optimum, or a negative error code:

| Code | Meaning |
|---|---|
| -2 | A SCIP call failed. |
| -3 | `SCIPcreate` failed. |
| -4 | A clique has more than 64 elements. |
| -5 | Not solved to optimality. |

### Loading it

The package loads the wrapper once per session with `ForeignFunctionLoad` and passes the arrays with `RawMemoryExport`. It looks for `a401118_scip.dll` (`.dylib`, `.so`) in `src/c/a401118_scip/lib`, or in the directory named by the environment variable `A401118_SCIP_LIB`. A failed lookup is remembered too, so restart the kernel after building. On Windows, a DLL's dependencies are found on `PATH`, not next to it, so the package first loads `libsoplexshared.dll` and `libscip.dll` from that directory with `LibraryLoad`.

### Hooking into A401118.wl

`A401118.wl`'s one-argument definitions, such as `A401118List[nmax_Integer?Positive]`, are more specific than definitions with `OptionsPattern[]`, so a plain call always reaches them first. They take their solver from the private `a401118DefaultSolver`. This package redefines that function, with the same left-hand side, to give the `Automatic` choice, and adds definitions with `OptionsPattern[]` for calls that have options. Loading `A401118.wl` again puts the `LinearOptimization` default back.

## Building the SCIP library

These steps were run on Windows with Visual Studio 2022 (MSVC 14.44, using its bundled CMake and Ninja) and SCIP Opt Suite 10.1.0. Run them from an "x64 Native Tools" prompt. Keep the SCIP build directory short (`C:\Users\sheng\AppData\Local\Temp\scip` here), because MSVC fails with `C1083` on long paths.

1. Download `scipoptsuite-10.1.0.tgz` from the [SCIP releases](https://github.com/scipopt/scip/releases) and unpack it, here to `<scip>\src`.
2. Build SCIP with SoPlex and nothing optional, as shared libraries:

   ```bat
   cmake -S <scip>\src -B <scip>\b -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=<scip>\inst ^
     -DAUTOBUILD=OFF -DGCG=OFF -DUG=OFF -DPAPILO=OFF -DZIMPL=OFF -DGMP=OFF -DMPFR=OFF -DREADLINE=OFF -DZLIB=OFF ^
     -DIPOPT=OFF -DAMPL=OFF -DBOOST=OFF -DCLIQUER=OFF -DJANSSON=OFF -DLUSOL=OFF -DQUADMATH=OFF -DSHARED=ON -DLPS=spx
   cmake --build <scip>\b --parallel
   cmake --install <scip>\b
   ```

3. Build the wrapper from the repository root. This writes `a401118_scip.dll` to `src/c/a401118_scip/lib`, and on Windows copies SCIP's DLLs there too (`build/` and `lib/` are in `.gitignore`):

   ```bat
   cmake -S src/c/a401118_scip -B src/c/a401118_scip/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DSCIP_DIR=<scip>/inst/lib/cmake/scip
   cmake --build src/c/a401118_scip/build
   ```

On macOS and Linux the same CMake steps apply. The wrapper is then `a401118_scip.dylib` or `.so`, and it finds SCIP through its build RPATH. That route has not been tried.

## Performance

Measured with Mathematica 15.0.1 on Windows, with SCIP 10.1.0 built as above. Each run starts from $n = 1$ and was checked against the b-file.

| | SCIP | `LinearOptimization` |
|---|---|---|
| One solve at $m = 198$ (173 variables, 721 cliques) | 0.75 s | 3.7 s |
| `A401118List[150]` | 5.0 s | 7.0 s |
| `A401118List[200]` | 16.3 s | 56.0 s |
| `A401118List[300]` | 82.6 s | 266.7 s |

Loading `A401118.wl` takes about 38 s, which is the compile of `lcmTrianglesC`. Loading this package on top adds no measurable time.

## Checks run

Run `test/wolfram/A401118_SCIP.wlt` (11 cases, about 1 minute). Without the SCIP library, the SCIP-only case passes trivially and the rest test the fallback. It checks:

- That the package adds no public names and puts `Method -> Automatic` on the three functions.
- That `Method -> "LinearOptimization"` gives the same 150 terms as `Automatic`.
- That `Automatic` picks SCIP exactly when the library is found.
- That plain calls go through `a401118DefaultSolver`, and that it gives the `Automatic` choice.
- That `Method -> "SCIP"`, when built, gives the right terms up to 150 and a valid witness for $n = 120$.
- That without the library, `Automatic` falls back and `"SCIP"` gives `::noscip`.
- The messages for an unknown method, and for a bad argument given together with an option.

Separately, `A401118List[300]` with SCIP and the SCIP witness for $n = 300$ were checked against the b-file.
