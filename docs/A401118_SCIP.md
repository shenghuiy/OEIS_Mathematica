# A401118_SCIP: SCIP for the A401118 integer programs

`src/wolfram/A401118_SCIP.wl` adds a `Method` option to the two packages that compute [A401118](https://oeis.org/A401118) with integer programs: [A401118ILP](A401118ILP.md) and [A401118Incremental](A401118Incremental.md). The option picks who solves their 0-1 programs: [SCIP](https://github.com/scipopt/scip), called through `ForeignFunctionLoad`, or the packages' own `LinearOptimization` code. The C code is in [`src/c/a401118_scip`](../src/c/a401118_scip).

Everything about SCIP is in this file and in `src/c`. `A401118ILP.wl` and `A401118Incremental.wl` contain no SCIP code, and the exhaustive search in [`A401118.wl`](A401118.md) is not touched.

## Loading and calling

From the repository root:

```wolfram
Get["src/wolfram/A401118_SCIP.wl"];   (* loads A401118ILP.wl and A401118Incremental.wl too, if they are not loaded yet *)
OEIS`A401118ILP[300]                                      (* 218, with SCIP if its library is built *)
OEIS`A401118ILP[300, Method -> "LinearOptimization"]      (* A401118ILP.wl's own solve *)
OEIS`A401118List[200, Method -> "SCIP"]                   (* fails with ::noscip if the library is missing *)
```

The package adds no public names. It puts the option on `A401118ILP`, and on `A401118Incremental`, `A401118List` and `LCMTriangleFreeSubset`. It also replaces their `::usage` text to mention it. `LCMTriangles` uses no solver, so it gets no option.

## The `Method` option

| `Method` | Solver |
|---|---|
| `Automatic` (default) | SCIP if [its library](#building-the-scip-library) is found, otherwise the package's own `LinearOptimization` code. |
| `"SCIP"` | SCIP. Without the library, gives a `::noscip` message and returns `$Failed`. |
| `"LinearOptimization"` | The package's own code, as if this file were not loaded. |

Any other value gives a `::method` message and returns `$Failed`, and so does a first argument that is not a positive integer (`::posint`). Calls without options, such as `A401118ILP[300]`, use `Automatic` once this package is loaded. All methods give the same values. The subsets may differ, though, since a largest subset is not unique. If SCIP returns an error code, the function gives a `::scipfail` message and solves that problem with `LinearOptimization` instead.

## How it works

### One kind of problem

Both packages reduce A401118 to the same 0-1 program. There is one variable for each number that lies in some LCM triangle. The goal is to maximize the number of variables set to 1, with at most two from each LCM clique. `A401118ILP` solves it once for $\lbrace 1..n\rbrace$. `A401118Incremental` solves it for $\lbrace 1..m\rbrace$ at those $m$ where its last largest subset does not extend.

`a401118SCIPSolve` takes the variables and cliques and returns the variables set to 1. That is the contract of `A401118Incremental.wl`'s `lcmTriangleMax`. For `A401118ILP`, `a401118SCIPILPSet` repeats `A401118ILP.wl`'s `a401118ILPSet` with SCIP in place of its `LinearOptimization` call. It builds the model with that package's `a401118Cliques`.

### The C wrapper

[`a401118_scip.c`](../src/c/a401118_scip/a401118_scip.c) is a small C function on top of SCIP's C API. It takes the model as flat arrays: the number of variables, their weights (all 1 here), and the cliques in compressed form, as start offsets plus 0-based variable indices. It builds one binary variable per number and one linear constraint $\sum x \le 2$ per clique, solves, and writes the 0-1 solution into an output array. It returns the optimum, or a negative error code:

| Code | Meaning |
|---|---|
| -2 | A SCIP call failed. |
| -3 | `SCIPcreate` failed. |
| -4 | A clique has more than 64 elements. |
| -5 | Not solved to optimality. |

### Loading it

The package loads the wrapper once per session with `ForeignFunctionLoad` and passes the arrays with `RawMemoryExport`. It looks for `a401118_scip.dll` (`.dylib`, `.so`) in `src/c/a401118_scip/lib`, or in the directory named by the environment variable `A401118_SCIP_LIB`. A failed lookup is remembered too, so restart the kernel after building. On Windows, a DLL's dependencies are found on `PATH`, not next to it, so the package first loads `libsoplexshared.dll` and `libscip.dll` from that directory with `LibraryLoad`.

### Taking over plain calls

Definitions with `OptionsPattern[]` handle the calls that have options. A one-argument definition such as `A401118ILP[n_Integer?Positive]` is more specific, though, so a plain call would still reach the package's own definition. This file therefore redefines the one-argument forms with the same left-hand sides, which replaces them, and sends them to `Method -> Automatic`. Loading `A401118ILP.wl` or `A401118Incremental.wl` again puts its own one-argument definitions back. The `Method` option keeps working either way.

## Building the SCIP library

These steps were run on Windows with Visual Studio 2022 (MSVC 14.44, using its bundled CMake and Ninja) and SCIP Opt Suite 10.1.0. Run them from an "x64 Native Tools" prompt. Keep the SCIP build directory short (`C:\Users\sheng\AppData\Local\Temp\scip` here), because MSVC fails with `C1083` on long paths.

1. Download `scipoptsuite-10.1.0.tgz` from the [SCIP releases](https://github.com/scipopt/scip/releases) and unpack it, here to `<scip>\src`.
2. Build SCIP with SoPlex and nothing optional, as shared libraries:

   ```bat
   cmake -S <scip>\src -B <scip>\b -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=<scip>\inst ^
     -DAUTOBUILD=OFF -DGCG=OFF -DUG=OFF -DPAPILO=OFF -DZIMPL=OFF -DGMP=OFF -DMPFR=OFF -DREADLINE=OFF -DZLIB=OFF ^
     -DIPOPT=OFF -DAMPL=OFF -DBOOST=OFF -DCLIQUER=OFF -DJANSSON=OFF -DLUSOL=OFF -DQUADMATH=OFF -DSHARED=ON -DLPS=spx
   cmake --build <scip>\b --parallel
   cmake --install <scip>\b
   ```

3. Build the wrapper from the repository root. This writes `a401118_scip.dll` to `src/c/a401118_scip/lib`, and on Windows copies SCIP's DLLs there too (`build/` and `lib/` are in `.gitignore`):

   ```bat
   cmake -S src/c/a401118_scip -B src/c/a401118_scip/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DSCIP_DIR=<scip>/inst/lib/cmake/scip
   cmake --build src/c/a401118_scip/build
   ```

On macOS and Linux the same CMake steps apply. The wrapper is then `a401118_scip.dylib` or `.so`, and it finds SCIP through its build RPATH. That route has not been tried.

## Performance

Measured with Mathematica 15.0.1 on Windows, with SCIP 10.1.0 built as above. Every value was checked against the b-file.

`A401118ILP[n]`, one program for $\lbrace 1..n\rbrace$:

| $n$ | $a(n)$ | SCIP | `LinearOptimization` |
|---|---|---|---|
| 100 | 76 | 0.07 s | 0.16 s |
| 200 | 146 | 1.8 s | 3.7 s |
| 300 | 218 | 5.2 s | 13.5 s |
| 400 | 290 | 12.1 s | 40.1 s |
| 500 | 356 | 38.3 s | |
| 656 | 464 | 365 s | |

With SCIP, every b-file term can be checked this way: $n = 656$, the last one, takes 6 minutes.

`A401118List[n]` from `A401118Incremental`, every term up to $n$:

| $n$ | SCIP | `LinearOptimization` |
|---|---|---|
| 150 | 5.0 s | 7.0 s |
| 200 | 16.3 s | 56.0 s |
| 300 | 82.6 s | 266.7 s |
| 500 | 1,681 s | |

Loading this package takes about 40 s when it has to load `A401118Incremental.wl`, which compiles `lcmTrianglesC`.

## Checks run

Run `test/wolfram/A401118_SCIP.wlt` (15 cases, about 40 s, most of it loading `A401118Incremental.wl`). Cases that can run `LinearOptimization` keep $n < 20$. Without the SCIP library, the SCIP-only case passes trivially and the rest test the fallback. It checks:

- That the package adds no public names, puts `Method -> Automatic` on the four functions, and leaves `A401118` without options.
- That $a(19) = 16$ from `A401118ILP` with every method, and that the incremental terms up to 19 agree between methods.
- That `Automatic` picks SCIP exactly when the library is found, and that plain calls go through it.
- That `"LinearOptimization"` runs the packages' own code (`a401118ILPSet`, `lcmTriangleMax`).
- That `Method -> "SCIP"`, when built, gives the right values and triangle-free subsets for $n = 120$ (incremental) and $n = 150$ (ILP).
- That without the library, `Automatic` falls back and `"SCIP"` gives `::noscip`.
- The messages for an unknown method and a bad first argument.
